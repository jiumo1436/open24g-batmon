### 修了什么

**1. 「测试读取选中」之后点 ×／取消，程序卡死或直接消失**

复现路径：`＋ 导入设备` → `浏览 configs` → `测试读取选中` → 立刻点 `×` 或 `取消`。

- 点 `取消`：界面**冻住十几秒**，标题栏挂「未响应」；
- 点 `×`：程序**直接消失**，`crash.log` 里只有「启动」记录，没有堆栈。

两个症状是**两个独立的 bug**，只修一个还会复发：

| 原因 | 说明 |
| --- | --- |
| 线程被对话框带走 | 测试线程挂成了对话框的子对象。对话框关闭时 Qt 会连带销毁它，而线程还在等设备回包 —— `QThread` 在「仍在运行」状态下析构会 `abort()` 整个进程，这就是点 × 后程序直接没掉的原因 |
| 界面线程死等 | 取消时在 UI 线程上同步等线程结束，最长 12 秒，而读取过程中根本不响应中断请求，等于白等。默认又勾选了全部 7 项，串行测完刚好撞上这个上限 |

修复后：取消操作**从最长 12 秒降到 0.16 秒**，对话框立刻关闭，进程正常退出。
线程改成交给主窗口统一回收，等它真的结束才释放引用。

**2. 「浏览 configs」把格式示例也列进了待导入列表**

`configs/templates/` 里是格式示例（VID 统一写成 `0x1234`，不对应任何真实硬件），
以前会跟实机配置一起列出来、还默认勾上，测试时自然读不到数，很容易被当成程序坏了。

现在整个 `templates/` 目录**不再进入导入列表**：列表从 7 项变成 4 项，全部是实机配置。
模板文件仍然随包分发，自己写配置时照样可以照着改。

### 怎么用

1. 解压，双击 `设备电量监控.exe`；
2. `＋ 导入设备` → `浏览 configs` → 勾选要监控的设备 → `导入选中`；
3. 第一次打开是空列表，这是正常的 —— 本程序不含任何内置设备协议。

已有旧版的话，把新的 exe 与 `_internal/` 覆盖过去即可，同目录的
`devices.json` / `user_settings.json` / `cache.json` 保持不动就不会丢配置。

详细说明见包内 `quick-start.txt`。

---

### 需要你知道的

- **配置格式没变**：0.2.6 及更早写好的配置可以直接用，不需要迁移。
- **`configs/templates/` 不是设备**：里面是语法示例，导入界面不会再列出它们；
  想用模板请自己复制一份改参数，放到 `configs/devices/` 下。
- **exe 哈希**：`a522f171…`（0.2.6 是 `d531e9c0…`），可用来确认下载的是这一版。
- **还是那句话**：配置能导入 ≠ 能读到数。第一次加新设备，请拿厂商软件显示的电量核对一下。

# 验证指南

本文档列出**不依赖我这边环境**、任何人都能照着做的验证步骤，用来确认软件满足
「配置驱动、无硬编码设备协议、异常不崩溃」的要求。

---

## 0. 准备

```bash
pip install -r requirements.txt
python app.py
```

或直接双击 `设备电量监控.exe`（`configs/` 放在 exe 同目录，且 `_internal/` 与 exe 同级）。

---

## 1. 无硬编码设备协议

```bash
# 源码里不该出现任何具体设备的 VID / 帧头 / 设备名
grep -nE "0x[0-9A-Fa-f]{4}" app.py | grep -v "0x" || echo "无 VID 字面量"
grep -nE "read_fixed17|read_session20|read_private64" app.py || echo "无内置读取器"
```

**界面验证**：把 `configs/` 清空（或改名），启动软件 —— 应该显示「0 台设备」，
不会自动识别任何设备、不会报错。清空 `devices.json` 后再启动同样应为 0 台。

---

## 2. 配置校验：中文报错、不崩溃

把下面内容存成 `坏配置.json` 并用「＋ 导入设备」导入：

```json
{ "devices": [ { "name": "坏设备", "match": { "vid": "0xZZZZ" },
  "read": { "query": ["AA BB"], "reply": { "battery": { "byte": 3 } } } } ] }
```

预期：弹窗提示「「坏设备」的 match.vid 不是合法的数字/十六进制：'0xZZZZ'」，
**程序不退出**，`devices.json` 不新增任何条目。

再试这几类，都应给出中文提示而不是英文异常堆栈：

| 错误 | 预期提示（关键词） |
| --- | --- |
| 少写 `read` | 缺少 read 段 |
| `battery.byte` 写字符串 | reply.battery.byte 必须是整数 |
| `version` 写 2 | 配置版本 2 不受支持 |
| JSON 少一个括号 | JSON 语法错误（第 X 行第 Y 列） |
| 导入 `configs/templates/template.json` | 这是配置模板，不是可导入的设备 |

命令行批量校验（不开界面）：

```bash
python tools/validate-config.py
```

## 3. 串口接收器

1. 打开「设置 → 串口接收器」，下拉框应列出本机串口（如 COM3 / COM4），第一项是
   「自动选择（逐个尝试）」；
2. 选择某个端口后，程序立刻重读一轮，卡片状态随之变化；
3. 所选端口写入 `user_settings.json` 的 `serial_port`，重启后保持；
4. 拔掉串口接收器（或选一个不存在的端口）：卡片显示「未连接 / 未响应」，
   **程序不崩溃**，插回后下一轮自动恢复。

配置里 `transport.port` 留空即跟随上面的选择；写死时以配置为准。

## 4. YAML 配置

把任意示例 JSON 改写成 `.yaml`（结构完全等价），导入应正常；语法写错时应提示
「YAML 语法错误（第 X 行第 Y 列）」。打包版 exe 已内置 PyYAML。

## 5. 电量换算能力

`docs/config-schema.md` 第 6.1 节有现成写法。可以用「测试读取选中」直接验证：

| 场景 | 配置片段 | 说明 |
| --- | --- | --- |
| 多字节 | `"bytes": 2, "order": "little", "scale": 0.1` | 两字节小端，0.1% 精度 |
| 抠位 | `"mask": "0x7F00", "shift": 8` | 取高字节低 7 位 |
| 查表 | `"map": [[0,0],[1,25],[2,60],[3,100]]` | 档位值映射成百分比 |
| 公式 | `"formula": "min(100, x*2-10)"` | 变量 `x` 是原始值 |
| 电压 | `"read_as": "voltage", "voltage_min": 3300, "voltage_max": 4200` | 电压线性映射 |

公式里写 `__import__('os')` 之类会被拒绝（AST 白名单），这是设计行为。

## 6. 托盘

| 设备数 | 预期 |
| --- | --- |
| 0 台 | 3 个浅灰空环（保证图标可见） |
| 1 台 | 1 个粗环 |
| 2 台 | 2 个环 |
| 3 台及以上 | 3 个环，只取电量最低的三台 |

- 外圈 = 三台里电量最低，内圈 = 三台里最高；
- 悬停提示列出**全部**设备，电量高的在上、最低的在最下；
- 左键唤起主界面；右键菜单有「退出软件」；退出后托盘无残留图标；
- 点窗口 × 只隐藏，进程仍在托盘。

---

## 7. 批量与性能

把 30~50 份配置放进 `configs/`（可分子文件夹）：

1. 「浏览 configs」应递归列出全部（跳过模板），表格滚动流畅；
2. 取消勾选部分设备后「测试读取选中」：界面**不卡死**（读取在后台线程）；
3. 导入后主界面自动刷新时，线程数封顶 8，一台慢设备不拖累其它卡片。

---

## 8. 异常与稳定性

| 操作 | 预期 |
| --- | --- |
| 运行中拔掉接收器 | 卡片转「未连接」，日志记录，不闪退 |
| 运行中插回接收器 | **不等下一轮定时**，约 1~3 秒内自动刷新出读数（状态变化触发补刷） |
| 电脑睡眠后唤醒 | 唤醒后自动刷新一轮；设备刚唤醒时读数可能偏旧，2.5 秒后会再补一次 |
| 设备关机再开机 | 开机后自动从「已关机 / 未响应」恢复成实际电量，无需手动点刷新 |
| 打开两个实例 | 第二个直接退出（单实例） |
| `devices.json` 手动改坏 | 启动时中文提示并忽略坏条目，其余设备照常加载 |
| `user_settings.json` 删掉/写坏 | 自动按默认值重建 |
| 连续运行数小时 | `error.log` 超过 1MB 自动滚存为 `error.log.1`，不会无限增长 |

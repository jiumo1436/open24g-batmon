# v0.2.1 · 状态变化即时刷新（通用）

这是一个修复版：把「设备状态一变就刷新」补全到**所有 2.4G 设备**，不再只对插拔接收器
和系统睡眠生效；并修掉主窗口按空格会误开「捕获报文」的问题。

**发布日期**：2026-11-04
**适用系统**：Windows 10 / 11（64 位）
**配置文件版本**：`version: 1`（与 0.2.0 / 0.1.0 完全兼容，**不需要改任何配置**）

### 修复与改进

- **键鼠睡醒后立刻刷新**：鼠标、键盘自己打盹属于设备级省电，Windows 不发任何消息，
  以前的实现要等下一轮定时（默认 20 秒）。现在改为读取系统的「最近一次键鼠输入时刻」，
  人一动鼠标或敲一下键盘，1~2 秒内就补读一次。
  - 不装钩子、不读键值、不需要管理员权限；
  - 只补读「本来读得到、这会儿读不到」的设备，全部在线时不会多刷；
  - 连续没起色就退避（4 秒起翻倍，最多 2 分钟），不会一边打字一边反复读取。

- **插拔接收器 / 设备上电下电**：新增处理设备树变化 `0x0007`。以前只认
  `0x8000 / 0x8004`，而这两个码需要程序预先向系统注册 HID 通知才会收到，所以
  「插拔自动刷新」实际经常不生效。现在两种都接，连发的事件合并成一次。

- **耳机这类不靠键鼠触发的设备**：接收器一直插着时，耳机开关机既不改变设备树、
  也没有键鼠输入，只能主动去问。新增分级快探，只问读不到的设备：
  - 关机 / 接收器不在：每 8 秒问一次，开机后最迟 8 秒出现在界面上；
  - 只是这轮没回包（睡着的键鼠）：每 32 秒问一次（键鼠本身有输入信号覆盖，
    不必频繁打扰）；
  - 全部在线时不产生任何额外读取。

- **修复：按空格误开「捕获报文」**：按钮会保留键盘焦点，用鼠标点过之后随手按空格
  就等于又点了一次。现在主窗口按钮不参与键盘焦点，空格不会再激活任何按钮。

### 占用

同一台机器、同样 3 台设备，与 0.2.0 打包版对照实测（稳定运行状态）：

| 指标 | 0.2.0 打包版 | 0.2.1 |
| --- | --- | --- |
| 私有内存 | 93.8 ~ 94.5 MB | 94.6 ~ 94.7 MB |
| 工作集 | 172 ~ 174 MB | 174 ~ 175 MB |
| 句柄 | 1451 ~ 1463 | 1454 ~ 1460 |
| CPU | 0.24 ~ 0.28%（含启动刷新） | 0.01%（稳定后） |

差异在 1MB 以内，属于测量噪声；新增的两个定时器（每 0.7 秒查一次输入时刻、
每 8 秒探一次读不到的设备）开销低于测量精度。

### 已知问题

- 关机回 `0` 假帧的设备仍需在配置里声明 `"zero_is_off": true`，否则仍显示 0%；
  程序不会自动判断（关机 0 与真没电在协议层完全一样，猜错代价更大）；
- 未声明 `zero_is_off` 的耳机，关机与休眠在协议层无法区分，只能按「未响应」处理，
  开机后靠 32 秒那一档快探兜底；
- 暂不支持蓝牙设备（本项目只处理 2.4G 接收器）；
- 部分设备在 USB 3.0 接口上偶发丢包，重试后恢复。

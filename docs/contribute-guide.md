# 社区贡献指南

本项目最需要的东西不是代码，而是**设备配置**。
你手上那台设备，可能正是别人买回来读不出电量的那一台 —— 一份经过实测的 JSON，就是最有价值的贡献。

本指南说清三件事：**提 PR 必须带什么**、**怎么提**、**维护者会审到什么程度**。

---

## 一、PR 硬性准入条件（不满足直接关闭）

新增一台设备的配置 PR，**必须同时**提供下面三项材料，缺一不可：

| # | 材料 | 要求 |
| --- | --- | --- |
| 1 | **配置文件** | 基于 [`configs/templates/template.json`](../configs/templates/template.json) 编写，通过 `tools/validate-config.py` 校验，文件名小写英文 + 连字符 |
| 2 | **原始抓包日志** | 对应这台设备的 `.pcap` / `.pcapng`（或 Bus Hound 导出的日志）。必须包含「查询帧 + 回包」的完整往返，能看到电量字节。**在 PR 里作为附件上传，不要提交进仓库** |
| 3 | **硬件实测证据** | 至少一张截图或一段录屏：软件卡片读出电量 **且** 与厂商软件显示的电量一致。文件里能看到设备名/型号更佳 |

除此之外：

- **贡献者本人必须真实持有该硬件**，并在自己的机器上完成过一次成功的电量读取。
  「照着别人的配置文件改字段」「用模拟数据跑通」都不算实测；
- 只改配置，**不要改 `app.py`**。通用引擎表达不了的协议，请先开 issue 讨论
  「如何把它做成通用能力」（例如新增校验算法 / 新增换算方式），讨论通过后再提代码 PR；
- 不接受一次 PR 塞进几十份来源不明的配置。**一台设备一个 PR**，便于审核与回溯；
- 配置里不得含 MAC 地址、设备序列号、个人文件路径、厂商账号信息（抓包前请先脱敏）。

> 没有实测证据的配置，即使 JSON 语法完全正确、看起来完全合理，**也不会被合并进主库**。
> 原因很简单：错误配置比没有配置更糟 —— 用户会以为设备不支持，或读到错的电量。

---

## 二、维护者的审核范围（请先理解这一点）

**维护者不可能拥有全部硬件。** 这是本项目的现实约束，也是「配置驱动 + 社区共建」这套设计存在的原因。

因此审核只覆盖以下内容：

| 审核项 | 具体检查 |
| --- | --- |
| JSON 语法 | 能否解析；`format` / `version` / `template` 是否合法 |
| 字段完整性 | `name`、`read`、`reply.battery.byte` 等必填项是否存在；类型是否正确 |
| 参数逻辑合理性 | 帧长度与 `pad_to` 是否自洽；`checksum` 的 `from/to/at` 是否落在帧内；`range` 是否合理；`battery.byte` 是否落在回包范围内 |
| 换算一致性 | `bytes`/`order`/`mask`/`shift`/`scale`/`voltage_*` 的组合是否说得通 |
| 命名与隐私 | 文件名规范；有无个人信息残留 |

审核**不包含**：

- ❌ 实物硬件验证 —— 维护者不会为了合并一份配置去购买该设备；
- ❌ 读数准确性复核 —— 以贡献者提供的实测截图/录屏为准；
- ❌ 长期兼容性保证 —— 厂商改固件导致偏移变化，由后续贡献者修正。

也就是说：**配置的真实性由贡献者负责，格式与逻辑由维护者把关。**
如果后续有用户反馈某份配置读不到或读数明显异常，维护者会要求贡献者补充证据，
必要时先移出主库（移动到 `configs/` 之外或直接删除），等修复后再合入。

## 三、提交步骤

### 1. 准备环境

```bash
git clone https://github.com/<你的用户名>/open24g-batmon.git
cd open24g-batmon
pip install -r requirements.txt
```

### 2. 新建分支

```bash
git checkout -b config/add-brand-model
```

分支名建议 `config/add-<品牌>-<型号>`，一台设备一个分支。

### 3. 添加配置

```bash
cp configs/templates/template.json configs/brand-model.json
# 编辑 configs/brand-model.json
```

编写方法见 [配置制作教程](config-making-guide.md)。写完先本地自检：

```bash
python tools/validate-config.py configs/brand-model.json
python tools/check-filenames.py
```

再打开软件，用「＋ 导入设备 → 选择协议文件 → 测试读取选中」确认真的能读到电量。

### 4. 提交

```bash
git add configs/brand-model.json
git commit -m "config: add Brand Model (VID 0x1234 / PID 0x1001)"
git push origin config/add-brand-model
```

### 5. 发起 PR

在 GitHub 上点「Compare & pull request」，**按模板填写**（仓库已内置
[`pull_request_template.md`](../.github/pull_request_template.md)），至少包含：

```markdown
## 设备信息
- 品牌型号：
- 设备类型：鼠标 / 键盘 / 耳机 / 手柄 / 其它
- 连接方式：2.4G 接收器（HID） / 串口
- VID / PID / usage_page：

## 实测情况
- 软件读出电量：__%
- 厂商软件显示：__%
- 是否一致：是 / 否（差异说明）
- 关机时表现：已关机（显示上次读数）/ 未连接 / 0%（是否配置 `zero_is_off`）
- 测试日期与系统版本：

## 证据（附件）
- [ ] 抓包日志：xxx.pcap（附在评论里）
- [ ] 实测截图 / 录屏（附在评论里）
- [ ] 本地通过 `validate-config.py`
```

**证据怎么附**：在 PR 的评论框里直接拖入 `.pcap`、截图、录屏（GitHub 会生成
`https://github.com/user-attachments/...` 链接）。不要 `git add` 这些文件 ——
仓库只保留配置本身，抓包文件既占体积又可能含隐私信息。

### 6. 审核与合并

- 自动检查（GitHub Actions）会跑配置校验，红色 × 表示有语法/字段问题，请先修；
- 维护者按第二节的范围人工审核，可能会请你补充 `contains` 锚点说明、放宽/收紧 `match` 条件等；
- 合并后你的名字会出现在 Release 说明的「新增设备配置」里。

## 四、会被拒绝的常见情形

| 情形 | 说明 |
| --- | --- |
| 没抓包、没实测截图 | 无法验证配置真实性，直接关闭 |
| 只写「能用，放心」 | 口说无凭，必须有材料 |
| 从别的仓库/论坛抄来的配置 | 未经本人实测，且可能侵犯他人权益 |
| 一个 PR 混入多台设备 + 代码改动 | 拆分：配置一个 PR，代码能力另一个 PR |
| 配置里带 MAC / 序列号 / 用户名 | 隐私问题，请脱敏后重提 |
| 文件名 `我的鼠标.json` / `MyMouse.json` | 违反命名规范，请改成 `brand-model.json` |
| 为了让某台设备读通而改 `app.py` | 设备适配只能走配置；引擎能力扩展需先讨论 |
| 把 `.pcap` / 截图提交进 `configs/` | 仓库不收录调试素材，请改为评论附件 |

## 五、其它类型的贡献

不只是配置，下面这些同样欢迎：

- **文档**：教程写得不清楚、步骤照做走不通，直接改 `docs/`；
- **引擎能力**：新的校验算法、新的换算方式（如分段线性、二维查表）。请先开 issue 说明
  「哪些设备需要它、现有字段为什么表达不了」，再动代码；
- **界面 / 体验**：托盘、提醒、配色相关的改进；
- **兼容性反馈**：某台设备在新固件上读数变了，开 issue 附上前后抓包对比。

代码类 PR 的要求：能说明动机、改动集中在单一功能、不引入新的重量级依赖、不破坏
「无硬编码设备协议」这条底线（**任何具体设备的 VID/PID/帧头都不允许出现在 `.py` 里**）。

## 六、许可与版权

- 本项目使用 [MIT 协议](../LICENSE)。提交 PR 即表示你同意你的贡献以 MIT 协议分发；
- 配置文件的版权归贡献者所有，你可以在自己的仓库/博客另行发布；
- 请确保你有权提交这些内容：抓包数据应来自**你自己拥有的硬件**，
  不要提交他人设备的数据、厂商私有文档或受保密协议约束的材料；
- 若权利人认为某份配置侵犯其权益，请开 issue 说明，维护者会先行下架再核实。

---

## 七、行为准则

- 对事不对人：审核意见针对配置，不针对贡献者；
- 不讨论破解、不索要固件、不提供绕过授权的方法 —— 本项目只做「自己设备上的电量读取」；
- 不发布他人隐私（截图里请遮掉序列号、账号、路径）。

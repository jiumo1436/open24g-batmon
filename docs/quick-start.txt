open24g-batmon 0.2.5  ·  2.4G 外设电量监控
================================================

【怎么用】

1. 双击「设备电量监控.exe」，程序会在任务栏旁边（托盘区）显示环形电量图标；
   双击图标或点右键 →「打开主界面」可以看到完整列表。
2. 首次启动是空列表，因为本程序不含任何内置设备协议。
3. 点界面左上角「＋ 导入设备」→「浏览 configs」→ 勾选要监控的设备 → 导入。
4. 导入后程序开始读取电量。笔记本内置电池、USB 接收器都可能被识别到，
   按需取消勾选即可。

【文件夹里都有什么 —— 别拆散】

设备电量监控.exe   ← 双击这个
_internal\         ← 运行时（Python + Qt，约 112MB），必须和 exe 同级
configs\           ← 待导入的配置样例，导入时才读
skills\            ← AI 技能包，让 AI 帮你写配置（用不上可以删，不影响软件）
协议库\            ← 导入/导出过的协议都在这儿留一份（首次导入后生成）

exe 单独拷到别处是打不开的，要挪位置就整个文件夹一起挪。
这样做是为了不在 %TEMP% 里留解包垃圾，也为了启动快 3~5 秒。

【configs 里面是什么】

configs\devices\     四份实机配置，导入即用：
  vxe-r1-se-plus.json   VXE R1 SE+ 鼠标        17 字节，取反校验
  vgn-f1-pro.json       VGN 蜻蜓 F1 Pro 鼠标   同族协议，回包多一个报告 ID
  aula-f87.json         狼蛛 F87 键盘          先握手再查询
  xiberia-t7.json       西伯利亚 T7 耳机       64 字节大报文

configs\templates\   模板与语法示例。这几份的 VID 统一写成 0x1234，不对应任何
                     真实硬件，导入后读不到数据 —— 作用是让你照着格式写自己的。

这四个不是「支持列表」，而是四种典型协议形态的参照。你的设备如果不在里面，
导入后不会匹配到接口，需要自己写一份配置（见下）。

【想支持你自己的设备】

去仓库拿模板和教程：
  https://github.com/jiumo1436/open24g-batmon
  configs\templates\template.json  字段逐行中文注释
  docs\config-making-guide.md      抓包 → 定位帧 → 写配置 → 验证，全流程
  docs\config-schema.md            每个字段的准确含义

不想自己啃协议？这个压缩包里就带着 AI 技能包，位置在 skills\24g-device-config。
把那个文件夹整个复制到 AI 客户端的技能目录，重启客户端就能用：

  WorkBuddy      C:\Users\你的用户名\.workbuddy\skills\   （目录不存在就自己建）
  Claude Code    放到项目的 .claude\skills\ 下

装好后说一句「我有个 XX 设备，能加上吗」，它会带你查 VID/PID、分析抓包、
定位电量字节，生成配置并校验。中途缺数据会停下来问你，不会瞎编参数。

不装 AI 也能用：skills\24g-device-config\scripts\ 里两个脚本独立可跑，只需要
Python 3，不用装 PySide6。
  analyze_frames.py     喂几帧回包，推断电量在第几字节、校验怎么算
  validate_config.py    校验写好的 JSON，规则和软件导入时完全一致

写好后放进 configs\ 目录，回到软件「＋ 导入设备」里勾选导入即可，不用改代码。
读取成功的话，欢迎把配置连同抓包日志和实测截图提 PR，让更多人用上。

【常见问题】

· 导入后一直显示「未响应」：检查 VID/PID 是否填对，接收器是否插在 USB 2.0 口上。
· 电量显示 0%：部分设备关机时仍会回数据，给配置加 "zero_is_off": true 即可。
· 开机自启、托盘图标颜色、低电量提醒：都在「设置」里。

【注意】

本程序不写注册表（仅开机自启会在启动项留一条记录），删除整个文件夹即可卸载。
个人偏好保存在同目录 user_settings.json，升级时覆盖 exe 不会丢。

程序意外退出、桌面图标突然消失时可以看同目录的日志：
  error.log   普通错误与慢读取（超过 1MB 自动滚存为 error.log.1）
  crash.log   进程级崩溃瞬间的线程栈（同样是 1MB 滚存）
这两个文件可以直接贴到 Issues 里，是排查问题最有用的信息。

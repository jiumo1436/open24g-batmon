### 这次修的是什么

**现象**：程序在后台跑着，没有任何提示就消失了。任务栏图标没了，也没有报错窗口，
重新打开一切正常，只是历史读数还在。

查下来是 Windows 事件日志里的三条记录：

```
Application Error 1000
故障模块：Qt6Core.dll    异常代码：0xc0000409    异常偏移：0x1ce68
```

`0xc0000409` 加这个偏移，是 Qt 在**主动调用 abort() 结束进程**，不是内存不够、
也不是被杀毒软件杀掉。用 Process Lasso 的日志核对过：没有任何「终止进程」的记录，
所以不是内存清理软件干的。

#### 1. 后台线程在「还在运行」时被回收（主因）

程序读设备电量的方式是「开一个后台线程去问，问完发个信号回来」。
原来的写法在收到信号时就把这个线程对象**立刻丢掉**，可那一刻线程其实还没真正结束 ——
Qt 认为它在运行，却要销毁它，于是直接 abort 整个进程。

改成：线程先交给一个「回收站」，每秒确认一次它真的结束了，才放掉引用。

#### 2. 同一台设备的重读线程可能卡死，导致卡片永久停更

当一台设备上一轮还读得到、这一轮突然读不到时，程序会原地重读一次，避免卡片闪
「未响应」。如果这次重读恰好卡在驱动里，之后这台设备的所有结果都会被拦掉，
卡片就冻住了。
现在给重读加了 20 秒上限，超时自动放弃、恢复正常刷新。

#### 3. 托盘图标刷新改到事件循环空闲时再做

Windows 有个限制：正在处理窗口消息（点菜单、切窗口）的时候，不允许发起某些
系统调用，否则会报 `0x8001010d`。托盘的图标和提示走的就是这条路。
现在把刷新推迟到当前操作结束之后执行，顺带把一轮刷新里的多次图标更新合并成一次。

#### 4. 顺带修的几处

| 问题 | 影响 |
| --- | --- |
| 导入对话框里点「测试读取」后马上关窗，可能留下还在跑的线程 | 极端情况下会让程序退出 |
| 刷新收尾某一步出错时，「读取中」的锁不会释放 | 界面卡在「正在读取」，要点一次刷新才能恢复 |
| 设置里选过的串口在拔掉后仍被沿用 | 串口设备一直显示「未响应」，且看不出原因 |
| 右键菜单、各种弹窗关闭后不回收 | 长时间挂着会缓慢占用内存 |
| 缓存文件里有一条坏数据，程序就起不来 | 现在坏的那条会被跳过，其余照常用 |
| 日志没有时间 | 现在每行都带 `[MM-DD HH:MM:SS]`，便于排查 |

### 需要你知道的

- **配置文件不用动**：`configs/` 的结构和字段与 0.2.2 完全一致。
- **旧版可以直接覆盖**：解压后替换整个目录即可，`devices.json`、`user_settings.json`、
  `cache.json` 都在 exe 同级，替换时注意别删掉这三个文件。
- **这次没有改动任何设备协议逻辑**：读电量的算法、帧格式、校验方式一行没变。

### 如果还遇到程序消失

程序会在同目录写 `crash.log`（崩溃瞬间的线程栈）和 `error.log`（运行日志，
带时间戳）。把这两个文件发到 Issues 里，就能直接定位到具体哪一行。

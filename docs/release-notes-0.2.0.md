# v0.2.0 · 关机识别与即时刷新

这个版本集中在两件事：**设备关机后不再显示成 0%**，以及**状态一变就立刻重读，不用等下一轮定时**。
同时打包方式从单文件改为目录版，启动不再往 `%TEMP%` 解包上百兆垃圾。

**发布日期**：2026-11-04
**适用系统**：Windows 10 / 11（64 位）
**配置文件版本**：`version: 1`（与 0.1.0 完全兼容，已有配置无需改动）

---

### 下载

| 文件 | 说明 |
| --- | --- |
| `open24g-batmon-0.2.0-win64.zip` | 免安装，解压即用（exe + `_internal/` + configs） |
| `open24g-batmon-0.2.0-win64.zip.sha256` | 校验和 |

解压后目录结构：

```
open24g-batmon-0.2.0-win64/
├── 设备电量监控.exe     # 双击这个
├── _internal/           # 运行时（Python + Qt，约 112MB），必须与 exe 同级
├── configs/             # 设备协议配置样例，可自行增删
├── quick-start.txt      # 使用说明
└── LICENSE
```

> **exe 不能单独拷走**，必须和 `_internal/` 一起。这是换成目录版的原因：
> 单文件版每次启动都要把 112MB 解包到 `%TEMP%\_MEIxxxxxx`，正常退出才清理，
> 崩溃或被强杀就永久残留。实测某台机器 3 天留下 87 个目录、8.9GB。

首次启动是空列表，点「＋ 导入设备 → 浏览 configs」导入需要的设备即可。

### 引擎与功能

- **关机 / 拔接收器保留上次读数**：以前设备关机时会显示 `0%`，让人误以为电池坏了；
  现在区分三种状态显示：

  | 情况 | 卡片显示 |
  | --- | --- |
  | 接收器掉线、被拔掉 | 未连接 · 上次读数 X%（标注读到的时间），永久保留 |
  | 接收器在、这轮没回包（休眠） | 未响应 · 上次读数 X%，30 分钟后抹成 — |
  | 关机回 0 假帧（需配置声明） | 已关机 · 上次读数 X%，永久保留 |

  旧读数不参与低电量提醒、也不计入「在线 X/N」，不会拿昨天的数字弹窗。

- **状态变化自动补刷**：插拔接收器、系统睡眠唤醒、设备刚开机时不必等定时轮询——
  - 接 `WM_DEVICECHANGE` / `WM_POWERBROADCAST`，分别延迟 700ms / 1500ms 补刷一次；
  - 每轮刷新前后对比设备状态，从「关机/休眠/没读到」翻转为「读到电量」时，2.5 秒后再补一次拿稳定值；
  - 多次事件合并成一次、撞上正在刷新就重试两次、60 秒内不重复补。

- **`zero_is_off` 提升为通用配置项**：不再是耳机专用的技巧，两份通用模板与 `configs/README.md`
  都加了说明与判断依据表。**默认仍为 `false`，程序不会自动判断**——关机回的 0 与真正用到 0%
  在协议层完全一样，猜错的代价是「设备其实已经没电，用户却以为只是关了」。

### 修复

- 修复：`max_workers must be greater than 0` —— 设备列表为空时刷新线程池参数越界，
  日志里反复报错（0.1.0 已编译的 exe 缺此守卫）。
- 修复：进程级崩溃（`0xc0000409` / `ucrtbase.dll`）没有任何痕迹。新增 `crash.log`，
  由 `faulthandler` 在崩溃瞬间落盘各线程栈（1MB 滚存）；线程内未捕获异常也通过
  `threading.excepthook` 记录。
- 修复：GitHub 将许可证识别为 `NOASSERTION`，现恢复为标准 MIT。

### 已知问题

- 关机回 `0` 假帧的设备需自行在配置里加 `"zero_is_off": true`，否则仍显示 0%；
- 暂不支持蓝牙设备（本项目只处理 2.4G 接收器）；
- 部分设备在 USB 3.0 接口上偶发丢包，重试后恢复。

### 从 0.1.0 升级（**注意：不是覆盖 exe**）

0.1.0 是单文件 exe，0.2.0 是目录版，两者结构不同，不能只替换 exe。

```powershell
# 1. 把 0.2.0 解压到一个新文件夹
# 2. 从旧目录把下面 4 项复制到新文件夹（旧目录保留不动，作为退路）
#      devices.json          已导入的设备列表
#      user_settings.json    配色 / 托盘 / 自启 / 提醒等偏好
#      协议库\                导入过的设备配置
#      configs\              你自己写过的配置
# 3. 从新文件夹启动，确认设备列表和读数都在
```

全新安装无需任何迁移。
